# Phase 9 -- UI Design Contract

> Visual and interaction contract for Telegram bot message formatting. Generated by gsd-ui-researcher, verified by gsd-ui-checker.
>
> **Medium:** Telegram messages (HTML parse_mode). No web frontend.

---

## Design System

| Property | Value |
|----------|-------|
| Tool | none |
| Preset | not applicable |
| Component library | none (Telegram Bot API messages) |
| Icon library | Unicode emoji (Telegram-native rendering) |
| Font | Telegram client default (not controllable) |

**Note:** This phase has no web UI. All visual output is Telegram messages using HTML parse_mode. Continues Phase 5/6 formatting conventions. New message types: /valuation command response, /fundamentals command response, daily report valuation summary section, QoQ alert lines.

---

## Spacing Scale

Not applicable -- Telegram controls message spacing. Line-break conventions (carried from Phase 5):

| Token | Value | Usage |
|-------|-------|-------|
| inline-gap | single space | Between emoji and text, between label and value |
| field-break | `\n` (newline) | Between fields within a valuation card |
| card-break | `\n\n` (blank line) | Between asset valuation rows in summary |
| section-break | `\n\n` + separator line | Between valuation summary and next report section |

Exceptions: none

---

## Typography

Telegram HTML parse_mode supports: `<b>`, `<i>`, `<code>`, `<pre>`, `<u>`, `<s>`, `<a>`. No font size or weight control.

| Role | HTML Tag | Usage |
|------|----------|-------|
| Heading | `<b>` | Section titles ("Valuation Summary", "Fundamentals Dashboard"), asset symbols |
| Body | plain text | Price values, ratios, percentage figures, scenario labels |
| Detail | `<i>` | Disclaimers, methodology notes, data source labels |
| Data | `<code>` | Not used in valuation messages (reserved for error codes per Phase 5) |

---

## Color

Not applicable -- Telegram does not support text color in messages. Semantic meaning conveyed via emoji.

### Emoji Semantic Map (Phase 9 additions)

| Context | Emoji | Meaning |
|---------|-------|---------|
| Undervalued (margin of safety > 20%) | U+1F7E2 green circle | Fair value above market price by significant margin |
| Fairly valued (margin between -5% and +20%) | U+1F7E1 yellow circle | Close to fair value |
| Overvalued (margin of safety < -5%) | U+1F534 red circle | Fair value below market price |
| Trend up (QoQ improvement) | U+2B06 up arrow | Ratio improved quarter-over-quarter |
| Trend down (QoQ decline) | U+2B07 down arrow | Ratio declined quarter-over-quarter |
| Trend flat (QoQ within 2pp) | U+2796 minus | Ratio stable quarter-over-quarter |
| Data warning | U+26A0 + U+FE0F warning | Data disclaimer, cross-validation discrepancy |
| Chart/stats | U+1F4CA bar chart | Fundamentals dashboard header |

**Inherited from Phase 5/6:** All verdict emojis (green/yellow/red circles), info, error, success, checkmark, cross mark emojis remain unchanged.

## Message Structure Contract

### /valuation Command Response (TBOT-09, D-16)

```
<b>Valuation -- {SYMBOL} ({asset_name})</b>

<b>Current Price:</b> Rp {price}
<b>Fair Value (DCF):</b> Rp {fair_value}
<b>Margin of Safety:</b> {emoji} {margin_pct}%

<b>Scenario Analysis</b>
Bull (25%): Rp {bull_value} ({bull_return}%)
Base (50%): Rp {base_value} ({base_return}%)
Bear (25%): Rp {bear_value} ({bear_return}%)

<b>Peer Comparison ({sector})</b>
P/E: {pe_value} (sector avg {sector_pe}) -- {rank_label}
P/B: {pb_value} (sector avg {sector_pb}) -- {rank_label}
EV/EBITDA: {ev_value} (sector avg {sector_ev}) -- {rank_label}

<i>Based on {period} financials. Last updated {date}.</i>
```

**Rules:**
- Price formatted in IDR with thousands separators: `Rp 8,250`
- Margin of safety emoji: green circle if > 20%, yellow circle if -5% to 20%, red circle if < -5%
- Scenario returns formatted as signed percentage: `+15.2%`, `-8.3%`
- Peer rank labels: "cheap", "fair", "expensive" based on position relative to sector median
- Rank label "cheap" when metric < sector median * 0.85, "expensive" when > sector median * 1.15, "fair" otherwise
- Source line always present in italics at bottom
- Message fits within single Telegram message (< 4096 chars)

### /valuation Crypto Response (D-18)

```
{info_emoji} Valuation not available for crypto assets -- use /report {SYMBOL} for signal analysis.
```

### /valuation No Data Response (D-20)

```
<b>Valuation -- {SYMBOL} ({asset_name})</b>

<b>Current Price:</b> Rp {price}
<b>Estimated Fair Value:</b> Rp {rough_estimate}
<b>Margin of Safety:</b> {emoji} {margin_pct}%

{warning_emoji} <i>Estimated from market data only -- no financial reports parsed yet. Accuracy is limited.</i>

Use /fundamentals {SYMBOL} for available ratio data.
```

**Rules:**
- Rough estimate uses yfinance-based multiples (P/E * EPS or P/B * BV)
- Warning emoji and disclaimer always shown when no PDF-extracted data available
- Suggestion to use /fundamentals for what is available

### /fundamentals Command Response (TBOT-13, D-17)

```
{chart_emoji} <b>Fundamentals -- {SYMBOL} ({asset_name})</b>

<b>Profitability</b>
Net Margin: {net_margin}% {trend_emoji} ({qoq_change})
ROE: {roe}% {trend_emoji} ({qoq_change})
Gross Margin: {gross_margin}% {trend_emoji} ({qoq_change})

<b>Valuation Ratios</b>
P/E: {pe}
P/B: {pb}
EV/EBITDA: {ev_ebitda}

<b>Leverage</b>
Debt/Equity: {de_ratio} {trend_emoji} ({qoq_change})

<b>Cash Flow</b>
Operating CF: Rp {ocf}
Free Cash Flow: Rp {fcf}
Capex: Rp {capex}

<i>Source: {source_label}. Period: {period}.</i>
```

**Rules:**
- QoQ change format: `+2.1pp` for percentage point changes, `+12.3%` for ratio changes
- Trend emoji: up arrow if improved, down arrow if declined, minus if stable (within 2pp for margins, within 5% for ratios)
- Source label: "IDX financial report" when PDF-extracted, "Market data (yfinance)" when using cached fundamentals
- All IDR values use thousands separators and appropriate unit abbreviation: `Rp 2.1T` (trillion), `Rp 450B` (billion), `Rp 12.3M` (million)
- When both PDF and yfinance data available, prefer PDF-extracted. Show source label accordingly

### /fundamentals Crypto Response (D-18)

```
{info_emoji} Fundamentals dashboard not available for crypto assets -- use /report {SYMBOL} for signal analysis.
```

### /fundamentals No Data Response

```
{chart_emoji} <b>Fundamentals -- {SYMBOL} ({asset_name})</b>

No fundamental data available yet.

The pipeline fetches financial data weekly. Check back after the next pipeline run, or use /valuation {SYMBOL} for a market-data estimate.
```

### Daily Report Valuation Summary Section (REPT-03, D-19)

Appended after the signal cards section, before the News section. Skipped entirely when no IDX stocks in watchlist.

```
<b>Valuation Summary</b>

{SYMBOL_1}: Rp {price} | FV Rp {fair_value} | {emoji} {margin}% MoS
{SYMBOL_2}: Rp {price} | FV Rp {fair_value} | {emoji} {margin}% MoS
{SYMBOL_3}: Rp {price} | FV Rp {fair_value} | {emoji} {margin}% MoS
```

**Rules:**
- One line per IDX stock in watchlist
- "FV" abbreviation for "Fair Value"
- "MoS" abbreviation for "Margin of Safety"
- Margin emoji: green circle if > 20%, yellow circle if -5% to 20%, red circle if < -5%
- Margin formatted as signed percentage: `+32%`, `-8%`
- Compact single-line format for quick scanning (D-19)
- When no PDF data available for a stock, show yfinance estimate with asterisk: `Rp 8,500*`
- Asterisk footnote at bottom: `<i>* Estimated from market data</i>`
- Section omitted entirely when zero IDX stocks in watchlist

### QoQ Alert Lines (VALN-05, D-21)

Inserted within the Valuation Summary section when significant QoQ changes detected after new quarterly report parsing.

```
<b>Valuation Summary</b>

{SYMBOL_1}: Rp {price} | FV Rp {fair_value} | {emoji} {margin}% MoS
{warning_emoji} Net margin dropped 5.2pp QoQ (28.1% -> 22.9%)
{SYMBOL_2}: Rp {price} | FV Rp {fair_value} | {emoji} {margin}% MoS
```

**Rules:**
- Alert line appears directly below the affected stock's summary line
- Indented with warning emoji prefix
- Shows: metric name, magnitude of change, previous -> current values
- Only shown when QoQ change exceeds threshold: margins > 3pp, ratios > 15%, revenue/profit > 10%
- Maximum 2 alert lines per stock (most significant changes only)
- Only triggered after new quarterly report parsing, not on every report cycle (D-21)

### Cross-Validation Discrepancy Alert (D-09)

When PDF-extracted values differ from yfinance by > 10%, included as a note in /fundamentals response:

```
{warning_emoji} <i>Revenue differs from market data by {pct}%. Manual review recommended.</i>
```

**Rules:**
- Inserted at bottom of /fundamentals response, before the source line
- Only shown when discrepancy > 10% for revenue or net profit
- Does not block the display of either data source

### Bot Command Responses

**`/valuation` success:** Full valuation message as specified above.

**`/valuation` missing argument:**
```
{error_emoji} Please specify an IDX stock symbol. Example: /valuation BBCA
```

**`/valuation` unknown symbol:**
```
{error_emoji} Symbol <code>{INPUT}</code> not found in your watchlist.

Use /watchlist to see your tracked assets.
```

**`/fundamentals` success:** Full fundamentals dashboard as specified above.

**`/fundamentals` missing argument:**
```
{error_emoji} Please specify an IDX stock symbol. Example: /fundamentals BBCA
```

**`/fundamentals` unknown symbol:**
```
{error_emoji} Symbol <code>{INPUT}</code> not found in your watchlist.

Use /watchlist to see your tracked assets.
```

### IDX Document Pipeline Alerts

**PDF download failure (sent via Telegram alert per D-05):**
```
{warning_emoji} Failed to download financial report for <b>{SYMBOL}</b> from IDX.

Using cached market data for valuation. Will retry next week.
```

**PDF parse failure:**
```
{warning_emoji} Failed to parse financial report for <b>{SYMBOL}</b>.

Valuation will use market data estimates until re-parse succeeds.
```

**New report parsed successfully (informational, included in daily report only):**
```
{info_emoji} New {period} report parsed for {SYMBOL}. Valuation updated.
```
