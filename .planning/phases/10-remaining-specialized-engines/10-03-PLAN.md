**src/data/onchain_fetcher.py (per D-07, D-08, D-10, D-11, D-12):**
Create async fetcher for on-chain data. Uses httpx (already in project) with tenacity retry.

```python
DEFILLAMA_BASE = "https://api.llama.fi"
CHAIN_MAP = {"BTC": "Bitcoin", "ETH": "Ethereum", "SOL": "Solana"}
```

Functions:
1. `async def fetch_tvl_history(symbol: str, days: int = 30) -> list[dict]`:
   - Map symbol to chain name via CHAIN_MAP. Return [] if not in map.
   - GET `{DEFILLAMA_BASE}/v2/historicalChainTvl/{chain}`
   - Returns list of {"date": unix_ts, "tvl": float}
   - Use httpx.AsyncClient with timeout=30s
   - Add 0.5s sleep between chain requests (rate limit per Pitfall 3)
   - Tenacity retry: 3 attempts, exponential backoff starting 2s

2. `async def fetch_onchain_data(symbol: str, asset_id: int, session: AsyncSession) -> list[dict]`:
   - Call fetch_tvl_history to get raw TVL data
   - Compute: tvl_current, tvl_7d_ago, tvl_30d_ago from history
   - Compute: tvl_7d_change = (current - 7d_ago) / 7d_ago, tvl_30d_change similarly
   - Store OnChainData rows via session.add() (using pg_insert for UPSERT on conflict)
   - Return dict: {"tvl_current": ..., "tvl_7d_change": ..., "tvl_30d_change": ..., "source": "defillama"}
   - On any exception: log warning, return empty dict (graceful degradation per D-09)

Note: CoinGecko exchange flow data may require Pro tier (Open Question 1 in RESEARCH.md). Implement TVL-only scoring first. If exchange flow is unavailable, the engine still works from TVL alone.

**src/engines/onchain.py (per D-09, D-11):**
Create OnChainEngine extending BaseEngine. Category "onchain". supports_stocks=False, supports_crypto=True.

Constructor: `__init__(self, onchain_data: dict[str, float] | None = None)` -- receives pre-fetched data.

analyze() implementation:
1. If self._data is None or empty, return score=0/confidence=0 with "No on-chain data available"
2. TVL scoring:
   - tvl_7d_change > 0.05 (5%): bullish (+0.4)
   - tvl_7d_change > 0.10 (10%): strongly bullish (+0.7)
   - tvl_7d_change < -0.05: bearish (-0.4)
   - tvl_7d_change < -0.10: strongly bearish (-0.7)
   - 30d change used as confirming signal: same direction adds 0.2, opposite subtracts 0.1
3. Exchange flow scoring (if available in data):
   - Net outflow (exchange_outflow > exchange_inflow): bullish (+0.3) -- accumulation signal
   - Net inflow: bearish (-0.3) -- sell pressure signal
   - If not available, skip (TVL alone is sufficient per D-09)
4. Final score: TVL score * 0.6 + exchange_flow_score * 0.4 (or TVL * 1.0 if no flow data)
5. Confidence: 0.3 base + 0.2 if both TVL and flow data available, +0.1 if 30d confirms 7d direction
6. indicators: {"tvl_current": ..., "tvl_7d_change": ..., "tvl_30d_change": ..., "exchange_net_flow": ..., "source": "defillama"}

**src/data/github_fetcher.py (per D-15, D-23):**
Create async fetcher for GitHub repo activity.

```python
CRYPTO_REPOS = {
    "BTC": "bitcoin/bitcoin",
    "ETH": "ethereum/go-ethereum",
    "SOL": "solana-labs/solana",
}
```

Functions:
1. `async def fetch_github_activity(symbol: str, asset_id: int, session: AsyncSession) -> dict | None`:
   - Look up repo in CRYPTO_REPOS. Return None if not found.
   - Read github_token from settings (import from src.config import settings)
   - Build headers: {"Accept": "application/vnd.github.v3+json"}, add Authorization if token present
   - GET `https://api.github.com/repos/{repo}` for stars, forks, open_issues
   - GET `https://api.github.com/repos/{repo}/stats/commit_activity` for weekly commits (last entry's "total")
   - Check X-RateLimit-Remaining header, log warning if < 10 remaining (Pitfall 4)
   - Store GitHubActivity row via session.add() with pg_insert UPSERT on conflict (asset_id, date)
   - Return dict: {"stars": int, "forks": int, "weekly_commits": int, "open_issues": int}
   - On any exception: log warning, return None (graceful degradation)
   - Use httpx.AsyncClient with timeout=15s
   - Tenacity retry: 2 attempts, wait 3s

**src/engines/alternative.py (per D-15):**
Create AlternativeDataEngine extending BaseEngine. Category "alternative". supports_stocks=False, supports_crypto=True.

Constructor: `__init__(self, github_data: dict[str, int | float] | None = None)` -- receives pre-fetched data.

analyze() implementation:
1. If self._data is None, return score=0/confidence=0 with "No alternative data available"
2. GitHub activity scoring:
   - weekly_commits: >50 = strong activity (+0.3), 20-50 = moderate (+0.1), <10 = low (-0.1), 0 = stale (-0.3)
   - stars: >50000 = established project (+0.1), <1000 = risky (-0.1)
   - open_issues relative to stars: issues/stars > 0.05 = concerning (-0.1), <0.01 = healthy (+0.1)
3. Activity trend (if weekly_commits_prev available in data):
   - Rising commits (current > prev * 1.1): bullish (+0.2)
   - Falling commits (current < prev * 0.8): bearish (-0.2)
4. Final score: sum of sub-scores, capped [-1, 1]
5. Confidence: 0.25 base. This is supplementary data, not primary signal.
6. indicators: {"weekly_commits": ..., "stars": ..., "forks": ..., "open_issues": ..., "source": "github"}
