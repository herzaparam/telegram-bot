Methods:

- `async def upsert_lesson(self, session, date, asset_type, engine_tags, topic, lesson_text, source_decision_id, times_observed=1)`:
  Use `pg_insert(Lesson).values(...)` with no conflict handling (new lessons get new rows; dedup merging is handled by `merge_lesson`).

- `async def merge_lesson(self, session, lesson_id, new_text, additional_observations=1)`:
  Update existing lesson: set `lesson = new_text`, increment `times_observed` by `additional_observations`, update `confidence_tier` based on new `times_observed` (hypothesis < 10, pattern 10-29, rule >= 30), set `updated_at = func.now()`.

- `async def get_valid_lessons(self, session, asset_type=None, engine_filter=None, limit=50) -> list[Lesson]`:
  Query `still_valid=True`. Optional filters: `asset_type` matches exactly or is `"all"`, `engine_filter` checks JSONB `engine_tags` contains the value. Order by `updated_at DESC`. Limit to `limit`.

- `async def get_relevant_lessons(self, session, asset_type, engine_categories, max_lessons=20) -> list[Lesson]`:
  Query `still_valid=True` AND `confidence_tier IN ('pattern', 'rule')` (per success criteria #2: not active until 10+ observations).
  Load all matching, score each with `_score_lesson()` (see research code example), sort descending, return top `max_lessons`.

- `_score_lesson(self, lesson, asset_type, engine_categories, now)` -> float:
  Multi-factor scoring per D-13: recency (linear decay over 90 days, weight 0.25), accuracy rate (times_correct/times_applied or 0.5 prior, weight 0.30), asset-type match (1.0 exact or "all", 0.3 mismatch, weight 0.25), engine relevance (fraction overlap, weight 0.20).

- `async def increment_times_applied(self, session, lesson_ids: list[int])`:
  `UPDATE lessons SET times_applied = times_applied + 1 WHERE id IN (:ids)`

- `async def update_lesson_accuracy(self, session, lesson_id, was_correct: bool)`:
  If `was_correct`: `UPDATE lessons SET times_correct = times_correct + 1 WHERE id = :id`
  (No-op if not correct -- only increment times_correct.)

- `async def invalidate_underperforming(self, session)`:
  Per D-09: `UPDATE lessons SET still_valid = false WHERE times_applied >= 5 AND (times_correct::float / times_applied) < 0.4 AND still_valid = true`

- `async def get_lessons_for_display(self, session, asset_type=None, engine_filter=None) -> dict`:
  Returns `{"recently_learned": [...], "top_lessons": [...]}` per D-16.
  "recently_learned": `still_valid=True, created_at >= now - 7 days`, order by `created_at DESC`, limit 10.
  "top_lessons": `still_valid=True, times_applied >= 3`, order by `(times_correct / times_applied) DESC`, limit 10.
  Each item is a dict with keys: `id, lesson, tier, times_observed, times_applied, accuracy, asset_type, engine_tags, topic, date`.

**1. Create `src/data/reflect.py`** implementing `reflect_stage` as a StageFunc (per D-01):

Module docstring: "Reflect stage: LLM-powered analysis of past decisions to extract lessons. Runs AFTER evaluate_stage in the pipeline. Analyzes mistakes and surprising wins, extracts lessons with dedup."

Import `EVAL_WINDOWS` from `src/data/evaluate` for window definitions.

Constants:
```python
# Max LLM calls per asset to prevent token budget explosion (Pitfall 1 from research)
MAX_ANALYSES_PER_ASSET = 3
# Max existing lessons shown for dedup context (Pitfall 2)
MAX_DEDUP_CONTEXT = 30
```

**`async def reflect_stage(session: AsyncSession, asset: Asset) -> None`** (per D-01, D-02, D-03):
- Bind structlog: `log = logger.bind(asset=asset.symbol, asset_id=asset.id)`
- Wrap entire body in try/except Exception, log exception, never crash pipeline.
- `today = date.today()`
- `analyses: list[dict] = []`
- For each `(window_name, window_delta)` in `EVAL_WINDOWS`:
  - `target_date = today - window_delta`
  - Get decision: `decision = await decision_repo.get_decision(session, asset.id, target_date)`. Skip if None.
  - Get evaluation: `evaluation = await evaluation_repo.get_evaluation(session, decision.id, window_name)`. Skip if None.
  - **D-03 filter**: Skip if `evaluation.was_correct and float(decision.confidence or 1.0) >= 0.4` (only analyze mistakes + surprising wins).
  - **Idempotency check** (Pitfall 4): Check if a lesson already exists for this decision: `SELECT 1 FROM lessons WHERE source_decision_id = :decision_id LIMIT 1`. If exists, skip.
  - Call `_analyze_decision(session, asset, decision, evaluation, window_name)`. If result, append to `analyses`.
  - Extract and store lesson: `await _extract_and_store_lesson(session, analysis, asset, decision)`.
  - Break if `len(analyses) >= MAX_ANALYSES_PER_ASSET`.
- **Lesson accuracy tracking** (Pitfall 3): For each evaluation processed, if `evaluation.was_correct` and decision has `lessons_applied` JSONB with lesson IDs, call `lesson_repo.update_lesson_accuracy(session, lesson_id, True)` for each lesson ID.
- Run `await lesson_repo.invalidate_underperforming(session)` (D-09).
- Log `reflect_complete` with count or `reflect_no_qualifying_decisions`.

**`async def _analyze_decision(session, asset, decision, evaluation, window_name) -> dict | None`** (per D-04, D-05):
- Get signals for the decision date: `signals = await signal_repo.get_signals_for_asset(session, asset.id, decision.date)`
- Build per-asset analysis prompt (D-05, D-07). System message:
  ```
  You are a trading analyst reviewing past decisions. Analyze what went right or wrong.
  Output valid JSON with exactly these keys:
  - analysis: string (100-200 words analyzing the decision outcome)
  - missed_signals: list of strings (signals that were ignored or underweighted)
  - overweighted_engines: list of strings (engines given too much weight)
  - underweighted_engines: list of strings (engines given too little weight)
  - lesson: string (one concrete lesson, max 150 characters)
  - weight_adjustments: dict mapping engine name to suggested weight change (-0.1 to +0.1)
  ```
- User message includes: asset symbol, decision date, verdict, score, confidence, actual change_pct, was_correct, window, and all signal summaries (category, score, confidence for each).
- Call `llm_completion(messages=messages, response_format={"type": "json_object"}, timeout=settings.timeout_decide_per_call)`.
- Parse response JSON. Validate required keys: `analysis, missed_signals, overweighted_engines, underweighted_engines, lesson, weight_adjustments`. Return None on parse failure (log warning).
- Return parsed dict with added `asset_symbol`, `asset_type`, `decision_id`, `window`.

**`async def _extract_and_store_lesson(session, analysis, asset, decision)`** (per D-10):
- Get existing valid lessons for dedup context: `existing = await lesson_repo.get_valid_lessons(session, asset_type=asset.asset_type, limit=MAX_DEDUP_CONTEXT)`.
- Build dedup prompt. System message:
  ```
  You are comparing a new lesson against existing lessons. Output valid JSON with:
  - action: "new" or "merge"
  - merge_target_id: int or null (ID of existing lesson to merge with, only if action="merge")
  - final_lesson_text: string (the lesson text to store -- either the new lesson or a merged version combining both)
  - topic: string (one of: momentum, volatility, trend, reversal, correlation, timing, risk, sentiment, macro, valuation, general)
  ```
- User message: the new lesson text from analysis, plus a numbered list of existing lessons with their IDs and text (truncated to 100 chars each).
- Call `llm_completion`. Parse response.
- If `action == "merge"` and `merge_target_id` is a valid existing lesson ID: call `lesson_repo.merge_lesson(session, merge_target_id, final_lesson_text)`.
- If `action == "new"`: determine `engine_tags` from `analysis["overweighted_engines"] + analysis["underweighted_engines"]` (deduplicated list). Call `lesson_repo.upsert_lesson(session, date=date.today(), asset_type=asset.asset_type, engine_tags=engine_tags, topic=topic, lesson_text=final_lesson_text, source_decision_id=decision.id)`.
- On any parse failure or LLM error, fall back to storing the raw lesson text from the analysis as a new lesson with topic="general".

**Batch cross-cutting pass** (D-04, D-06): The batch pass is NOT per-asset. Add a module-level list `_batch_analyses: list[dict] = []` that accumulates analyses across all asset calls within a pipeline run. Add a function `async def run_batch_cross_cutting(session: AsyncSession) -> None` that:
- If `len(_batch_analyses) < 2`, skip (nothing to cross-cut).
- Build prompt with all accumulated per-asset analyses summarized.
- System: "Extract 1-3 cross-cutting lessons that apply across all assets. Output JSON: {lessons: [{lesson: string, topic: string, engine_tags: list[str]}]}"
- Call LLM, parse, store each lesson with `asset_type="all"`.
- Clear `_batch_analyses`.
This function will be called from `src/pipeline/main.py` after all reflect_stage calls complete (similar to how report runs post-pipeline).
