# Phase 6 — UI Design Contract

> Visual and interaction contract for Telegram bot message formatting. Generated by gsd-ui-researcher, verified by gsd-ui-checker.
>
> **Medium:** Telegram messages (HTML parse_mode). No web frontend.

---

## Design System

| Property | Value |
|----------|-------|
| Tool | none |
| Preset | not applicable |
| Component library | none (Telegram Bot API messages) |
| Icon library | Unicode emoji (Telegram-native rendering) |
| Font | Telegram client default (not controllable) |

**Note:** This phase has no web UI. All visual output is Telegram messages using HTML parse_mode. Continues Phase 5 formatting conventions. New message types: daily report scorecard section, /scorecard command response.

---

## Spacing Scale

Not applicable -- Telegram controls message spacing. Line-break conventions (carried from Phase 5):

| Token | Value | Usage |
|-------|-------|-------|
| inline-gap | single space | Between emoji and text, between label and value |
| field-break | `\n` (newline) | Between fields within a scorecard item |
| card-break | `\n\n` (blank line) | Between evaluation window sections |
| section-break | `\n\n` + separator line | Between scorecard section and signals section in daily report |

Exceptions: none

---

## Typography

Telegram HTML parse_mode supports: `<b>`, `<i>`, `<code>`, `<pre>`, `<u>`, `<s>`, `<a>`. No font size or weight control.

| Role | HTML Tag | Usage |
|------|----------|-------|
| Heading | `<b>` | Section titles ("Yesterday's Scorecard"), window headers ("24h Results") |
| Body | plain text | Asset symbols in result lines, percentage values, verdict labels |
| Detail | `<i>` | Trend summary line, explanatory footnotes |
| Data | `<code>` | Not used in scorecard (reserved for error codes per Phase 5) |

---

## Color

Not applicable -- Telegram does not support text color in messages. Semantic meaning conveyed via emoji.

### Emoji Semantic Map (Phase 6 additions)

| Context | Emoji | Meaning |
|---------|-------|---------|
| Correct prediction | `checkmark` U+2705 | Decision was correct at this evaluation window |
| Wrong prediction | `cross mark` U+274C | Decision was incorrect at this evaluation window |
| Trend up | `arrow up` (text "^" in trend line) | Win rate improving week-over-week |
| Trend down | `arrow down` (text "v" in trend line) | Win rate declining week-over-week |
| Trend flat | `dash` (text "-") | Win rate stable week-over-week |
| Trophy | `trophy` U+1F3C6 | Best engine label in scorecard |
| Warning | `warning` U+26A0 + U+FE0F | Worst engine label in scorecard |

**Inherited from Phase 5:** All verdict emojis (green/yellow/red circles), info, error, success emojis remain unchanged.

## Message Structure Contract

### Daily Report Scorecard Section (REPT-01, D-15, D-16, D-17, D-18)

Prepended to the daily report, before the signal cards. Skipped entirely when no prior decisions exist (D-18).

```
<b>Yesterday's Scorecard</b>

<b>24h Results (4/6)</b>
checkmark BTC -- BUY -> +3.2%
checkmark BBCA -- STRONG BUY -> +1.8%
cross_mark ETH -- BUY -> -2.1%
checkmark TLKM -- HOLD -> +0.5%
cross_mark BBRI -- SELL -> +0.8%
checkmark SOL -- SELL -> -4.3%

<b>7d Results (2/3)</b>
checkmark BTC -- BUY -> +8.7%
cross_mark BBCA -- HOLD -> +6.2%
checkmark ETH -- SELL -> -5.1%

<i>Trending: 68% win rate this week (^ from 60% last week)</i>
```

**Rules:**
- Each evaluation window that matured gets its own subsection (D-16)
- 24h results shown first, then 3d, 7d, 30d in order
- Window header shows correct/total count in parentheses
- Each result line: `{correct_emoji} {SYMBOL} -- {VERDICT} -> {sign}{change_pct:.1%}`
- Percentage always shows 1 decimal place with explicit sign: `+3.2%`, `-1.5%`, `+0.0%`
- Trend line at bottom in italics (D-17): "Trending: {N}% win rate this week ({direction} from {N}% last week)"
- Direction indicators: `^` for up, `v` for down, `~` for flat (within 2pp)
- When only one window matured, omit the other subsections
- When zero evaluations matured, skip the entire scorecard section

### /scorecard Command Response (TBOT-04, D-12, D-13, D-14)

```
<b>Scorecard - Last 30 Days</b>

<b>Win Rate by Window</b>
24h: 65% (39/60)
 3d: 62% (37/60)
 7d: 58% (29/50)
30d: 52% (16/31)

<b>Total Decisions:</b> 60

<b>Best Engine:</b> trophy Technical (72% at 24h)
<b>Worst Engine:</b> warning Quantitative (48% at 24h)

<b>vs Buy & Hold</b>
BTC: Signals +12.4% | B&H +8.1% | <b>+4.3% alpha</b>
BBCA: Signals +3.2% | B&H +5.1% | <i>-1.9% underperform</i>
ETH: Signals +7.8% | B&H +6.0% | <b>+1.8% alpha</b>
```

**Rules:**
- Title shows selected period: "Last 7 Days", "Last 30 Days", "Last 90 Days", "All Time"
- If asset filter applied: title becomes "Scorecard - BTC - Last 30 Days"
- Win rate per window: aligned with padding, format `{N}%  ({correct}/{total})`
- Best/worst engine determined by 24h accuracy (D-12)
- Buy-and-hold comparison per asset (D-14): positive alpha in bold, negative in italic
- Alpha format: `+{N}% alpha` or `-{N}% underperform`
- Message splitting: apply existing `split_report()` logic if content exceeds 4096 chars

### /scorecard Asset-Filtered Response

```
<b>Scorecard - BTC - Last 30 Days</b>

<b>Win Rate by Window</b>
24h: 70% (14/20)
 3d: 65% (13/20)
 7d: 60% (9/15)
30d: 55% (6/11)

<b>Total Decisions:</b> 20

<b>Best Engine:</b> trophy Technical (78% at 24h)
<b>Worst Engine:</b> warning Quantitative (45% at 24h)

<b>vs Buy & Hold</b>
BTC: Signals +12.4% | B&H +8.1% | <b>+4.3% alpha</b>

<b>Recent Calls</b>
checkmark 2026-03-23 BUY -> +3.2% (24h)
cross_mark 2026-03-22 HOLD -> +5.8% (24h)
checkmark 2026-03-21 BUY -> +1.1% (24h)
```

**Rules:**
- Same structure as unfiltered, but scoped to single asset
- "Recent Calls" section added: last 5 evaluated decisions for this asset at 24h window
- Date format: YYYY-MM-DD

### /scorecard Empty State

```
info No scorecard data available yet.

Signals need at least one day to be evaluated. Check back after the pipeline has run for two consecutive days.
```

### /scorecard Period-Only Empty State

```
info No evaluations in the last 7 days.

Try a longer period: /scorecard 30d
```

## Copywriting Contract

| Element | Copy |
|---------|------|
| **Primary CTA** | "View accuracy stats" (shown via /scorecard) |
| **Empty state heading** | "No scorecard data available yet." |
| **Empty state body** | "Signals need at least one day to be evaluated. Check back after the pipeline has run for two consecutive days." |
| **Error state** | "Failed to load scorecard data. Try again in a few minutes." |
| **Period empty** | "No evaluations in the last {N} days. Try a longer period: /scorecard 30d" |

### Bot Command Responses

**`/scorecard` success:** Full scorecard message as specified above.

**`/scorecard` invalid period:**
```
cross_mark Invalid period. Use: 7d, 30d, 90d, or all.

Example: /scorecard 30d BTC
```

**`/scorecard` unknown asset:**
```
cross_mark Asset <code>{INPUT}</code> not found in your watchlist.

Use /watchlist to see your tracked assets.
```

### Daily Report Integration

**Report with scorecard (normal flow):**
```
{scorecard_section}

---

<b>Daily Signal Report - {YYYY-MM-DD}</b>
{... existing report format from Phase 5 ...}
```

- Horizontal rule (`---` rendered as text separator, or `\n\n` blank line) between scorecard and signals
- Scorecard is part of message 1; if it causes overflow, signals start in message 2

**Report without scorecard (first day, D-18):**
Report starts directly with the header -- no scorecard section, no blank space.
