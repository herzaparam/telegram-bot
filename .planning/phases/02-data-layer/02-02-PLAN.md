       - Return `(state.current_delay_seconds, state.consecutive_failures)`

       - Load BackoffState row for source
       - Set `consecutive_failures = 0`, `last_success_at = datetime.now(timezone.utc)`, `current_delay_seconds = 1.0` (reset to base)
       - `await session.commit()`

    4. **Helper: `async def _update_backoff_failure(session: AsyncSession, source: str) -> None`:**
       - Load BackoffState row for source
       - Increment `consecutive_failures += 1`
       - Set `last_failure_at = datetime.now(timezone.utc)`
       - Double delay with cap: `current_delay_seconds = min(state.current_delay_seconds * 2, 300.0)` (cap at 5 minutes)
       - `await session.commit()`

    5. `async def ingest_stage(session: AsyncSession, asset: Asset) -> None`:
       - This matches `StageFunc = Callable[[AsyncSession, Asset], Awaitable[None]]`
       - Determine fetcher: if `asset.asset_type == "stock"` use IDXStockFetcher, else CryptoFetcher
       - **Read adaptive backoff state** (per user decision: "Adaptive backoff state persisted in DB across pipeline runs"):
         - `delay_seconds, failures = await _read_backoff_state(session, fetcher.source_name)`

         - Log: `logger.info("adaptive_backoff_applied", source=fetcher.source_name, delay=delay_seconds, prior_failures=failures)`
       - Get latest stored date via raw asyncpg connection (extract URL from settings, create asyncpg connection for hot path):
         ```python
         raw_url = settings.database_url.replace("postgresql+asyncpg://", "postgresql://")
         ```

       - Call `get_latest_date(conn, asset.id)` to determine start date
       - **Determine fetch range with weekly re-fetch logic** (per user decision: "Daily runs fetch only missing days (delta); once per week re-fetch the full recent month to catch corrections"):

         - Elif latest is None:
           - Start from 2 years ago (auto-backfill per CONTEXT.md decision)
         - Else:
           - Start from `latest + timedelta(days=1)` (normal delta fetch)
         - End: today
       - If start > end: no new data needed, return early
       - Try: call `fetcher.fetch(asset.id, symbol, start, end)` where symbol is `asset.yfinance_symbol` for stocks or `asset.ccxt_symbol` for crypto
       - **On success: update backoff state** — `await _update_backoff_success(session, fetcher.source_name)`
       - Validate with `validate_rows(rows, asset.symbol)`
       - If rejected rows, log them (validation module already logs individually)
       - Upsert valid rows: `upsert_prices(conn, valid_rows)` — weekly re-fetch rows silently overwrite via ON CONFLICT UPDATE (per user decision: "Weekly refresh uses silent UPSERT")
       - For crypto: also fetch hourly candles for last 7 days, upsert to "price_history_hourly" table
