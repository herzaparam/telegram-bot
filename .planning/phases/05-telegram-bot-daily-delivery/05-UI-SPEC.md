# Phase 5 — UI Design Contract

> Visual and interaction contract for Telegram bot message formatting. Generated by gsd-ui-researcher, verified by gsd-ui-checker.
>
> **Medium:** Telegram messages (HTML parse_mode). No web frontend.

---

## Design System

| Property | Value |
|----------|-------|
| Tool | none |
| Preset | not applicable |
| Component library | none (Telegram Bot API messages) |
| Icon library | Unicode emoji (Telegram-native rendering) |
| Font | Telegram client default (not controllable) |

**Note:** This phase has no web UI. All visual output is Telegram messages using HTML parse_mode. Typography, spacing, and color are constrained by Telegram's rendering engine. The contract below specifies message structure, emoji usage, copywriting, and formatting rules within those constraints.

---

## Spacing Scale

Not applicable -- Telegram controls message spacing. The following line-break conventions apply:

| Token | Value | Usage |
|-------|-------|-------|
| inline-gap | single space | Between emoji and text, between label and value |
| field-break | `\n` (newline) | Between fields within an asset card |
| card-break | `\n\n` (blank line) | Between asset cards |
| section-break | `\n\n` + separator line | Between report header and first card |

Exceptions: none

---

## Typography

Telegram HTML parse_mode supports: `<b>`, `<i>`, `<code>`, `<pre>`, `<u>`, `<s>`, `<a>`. No font size or weight control.

| Role | HTML Tag | Usage |
|------|----------|-------|
| Heading | `<b>` | Report title, section headers, asset symbols |
| Body | plain text | Score values, confidence, verdict label |
| Detail | `<i>` | Reasoning summaries, explanatory notes |
| Data | `<code>` | Symbol names in inline references, error codes |

---

## Color

Not applicable -- Telegram does not support text color in messages. Semantic meaning is conveyed via emoji.

### Emoji Semantic Map

| Verdict | Emoji | Meaning |
|---------|-------|---------|
| STRONG BUY | `🟢🟢` | Double green circle -- strongest bullish signal |
| BUY | `🟢` | Green circle -- bullish signal |
| HOLD | `🟡` | Yellow circle -- neutral / wait |
| SELL | `🔴` | Red circle -- bearish signal |
| STRONG SELL | `🔴🔴` | Double red circle -- strongest bearish signal |
| LLM_UNAVAILABLE | `⚪` | White circle -- fallback verdict, LLM was unreachable |
| Warning | `⚠️` | Risk warning in header or failure notice |
| Success | `✅` | Confirmation of successful action (add/remove/settings) |
| Error | `❌` | Failed action or invalid input |
| Info | `ℹ️` | Informational status (e.g., "no data yet") |
| Clock | `🕐` | Delivery time setting |

## Message Structure Contract

### Report Header (D-07)

```
<b>Daily Signal Report - {YYYY-MM-DD}</b>
Assets: {N} | BUY: {n} | HOLD: {n} | SELL: {n}
⚠️ {risk_warning_1} | {risk_warning_2}
```

- Date format: YYYY-MM-DD (ISO 8601)
- Sentiment distribution shows only non-zero categories
- Risk warnings line omitted when no warnings exist
- Header is always the first message when splitting (D-08)

### Asset Card (D-06)

```
{emoji} <b>{SYMBOL}</b> ({asset_name})
   {VERDICT} | Score: {+0.00} | Conf: {00%}
   <i>{reasoning_truncated_to_100_chars}...</i>
```

- Score formatted as signed float with 2 decimal places: `+0.42`, `-0.15`
- Confidence formatted as integer percentage: `85%`
- Reasoning truncated at 100 characters, broken at word boundary, with ellipsis
- Indentation: 3 spaces before verdict line and reasoning line

### Single-Asset Detail (/report ASSET, TBOT-03)

```
<b>{emoji} {SYMBOL} ({asset_name})</b>

<b>Verdict:</b> {VERDICT}
<b>Score:</b> {+0.00}
<b>Confidence:</b> {00%}

<b>Reasoning:</b>
<i>{full_reasoning_text}</i>

<b>Key Factors:</b>
{key_factors_text}

<b>Risk Warning:</b>
{risk_warning_or_none}
```

- Full reasoning shown (not truncated)
- Key factors from DailyDecision.key_factors field
- Risk warning shown if present, otherwise "None" or line omitted

### Message Splitting (D-08)

- Maximum message length: 4096 characters (Telegram limit)
- Split at asset card boundaries -- never mid-card
- First message: full report header + as many cards as fit
- Subsequent messages: continuation mini-header + remaining cards
- Continuation mini-header format: `<b>... continued ({N})</b>`
- Each message must be valid HTML on its own

## Copywriting Contract

| Element | Copy |
|---------|------|
| **Primary CTA** | "Add assets to your watchlist" (shown in /start) |

### /start Welcome Message (TBOT-01, D-13)

```
✅ <b>Welcome to Trade Signal Agent</b>

I deliver daily trading signals for IDX stocks and crypto assets.

<b>Get started:</b>
1. Add assets: /add BBCA or /add BTC
2. View watchlist: /watchlist
3. Get today's report: /report
4. Get single asset: /report BTC
5. Change delivery time: /settings

Your watchlist is empty. Add your first asset to start receiving daily reports.
```

### /watchlist Display (WTCH-03)

**With assets:**
```
<b>Your Watchlist ({N} assets)</b>

1. <b>BBCA</b> - Bank Central Asia (IDX)
2. <b>BTC</b> - Bitcoin (Crypto)
3. <b>TLKM</b> - Telkom Indonesia (IDX)
```

**Empty state:**
```
<b>Your Watchlist</b>

No assets in your watchlist yet.

Add assets with /add BBCA or /add BTC
```

### /add Responses (WTCH-01, D-11, D-12)

**Success (existing asset):**
```
✅ Added <b>{SYMBOL}</b> ({asset_name}) to watchlist.
```

**Success (new asset, no price history, D-12):**
```
✅ Added <b>{SYMBOL}</b> ({asset_name}) to watchlist.

ℹ️ Price data will be fetched on next pipeline run. Signals available tomorrow.
```

**Already in watchlist:**
```
ℹ️ <b>{SYMBOL}</b> is already in your watchlist.
```

**Invalid symbol:**
```
❌ Symbol <code>{INPUT}</code> not found.

Check the symbol and try again. Examples:
- IDX stocks: /add BBCA, /add TLKM
- Crypto: /add BTC, /add ETH
```

### /remove Responses (WTCH-02)

**Success:**
```
✅ Removed <b>{SYMBOL}</b> from watchlist.
```

**Not in watchlist:**
```
ℹ️ <b>{SYMBOL}</b> is not in your watchlist.
```

### /settings Responses (TBOT-07, D-17)

**Display current:**
```
🕐 <b>Settings</b>

Delivery time: {HH:MM} WIB
```

**Update success:**
```
✅ Delivery time updated to <b>{HH:MM} WIB</b>.
```

**Invalid time:**
```
❌ Invalid time. Delivery time must be between 06:00 and 09:00 WIB.

Usage: /settings time 07:00
```

### /report Empty State (TBOT-02)

**No watchlist:**
```
ℹ️ No assets in your watchlist. Add assets first with /add BBCA
```

**No decisions today:**
```
ℹ️ No signals available yet for today. The pipeline runs daily at {HH:MM} WIB.
```

### Pipeline Failure Notices (D-18)

**Partial failure:**
```
⚠️ {N} assets failed analysis ({SYMBOL_1}, {SYMBOL_2}). Partial report below.
```
- Inserted between report header and first asset card

**Full pipeline failure:**
```
⚠️ <b>Pipeline Failed</b>

Today's signal report could not be generated. The team has been notified.
```

### Error States

**Unknown command:**
```
❌ Unknown command. Type /start to see available commands.
```

**Missing argument:**
```
❌ Please specify a symbol. Example: /add BBCA
```

### Destructive Actions

| Action | Confirmation Approach |
|--------|----------------------|
| /remove ASSET | No confirmation -- immediate removal. Reversible via /add. Low-risk action |
