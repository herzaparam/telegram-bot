  <action>
Fix the DD flags loading in src/data/decide.py (lines 254-273) to prevent coroutine objects from leaking to build_decision_prompt.

The root cause: when tests use `session = AsyncMock()`, calling `session.execute(dd_stmt)` returns an AsyncMock, and `.scalar_one_or_none()` on that returns a coroutine object (not None or a list). The coroutine is truthy, so `if dd_row:` passes, `dd_flags = dd_row` assigns the coroutine, and `len(dd_flags)` at line 271 raises TypeError. The except catches this, BUT dd_flags was already assigned to the coroutine on line 270 before the len() call on line 271. So dd_flags leaks out as a coroutine.

Apply fix: Add a type guard AFTER the try/except block, before line 296. Insert this between line 273 and 275:

```python
    # Guard: ensure dd_flags is actually a list (not a coroutine from mocked session)
    if dd_flags is not None and not isinstance(dd_flags, list):
        dd_flags = None
```

This is the safest fix because:
- It protects against the specific coroutine leak from mocked sessions
- It protects against any other unexpected type from DB edge cases
- It does NOT require changing any test mocks (the 6 tests should pass as-is)
- It preserves the existing try/except structure

Do NOT change the test files unless the tests still fail after the production fix. The 6 failing tests should pass once dd_flags is guaranteed to be list|None.
