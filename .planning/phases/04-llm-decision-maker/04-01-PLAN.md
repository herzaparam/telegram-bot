  <behavior>
    DecisionResult dataclass:
    - Frozen dataclass with fields: verdict, score, confidence, reasoning, key_factors, risk_warning, all_signals

    Contradiction detection:
    - Two signals with scores >+0.3 and <-0.3 respectively, both confidence >0.5, produces contradiction string
    - Two signals both positive does NOT produce contradiction
    - Signal with confidence <0.5 does NOT trigger contradiction even with opposite scores

    Deterministic fallback:
    - Empty signals list returns HOLD with score=0.0, confidence=0.0
    - Weighted score >0.6 returns STRONG BUY
    - Weighted score >0.2 returns BUY
    - Weighted score between -0.2 and 0.2 returns HOLD
    - Weighted score <-0.2 returns SELL
    - Weighted score <-0.6 returns STRONG SELL
    - Confidence capped at 0.5 max
    - risk_warning contains "LLM unavailable"
    - Reasoning contains "Deterministic fallback"

    LLM response parsing:
    - Valid JSON with all 6 fields returns DecisionResult
    - Score clamped to [-1.0, 1.0], confidence clamped to [0.0, 1.0]
    - Verdict validated against {"STRONG BUY", "BUY", "HOLD", "SELL", "STRONG SELL"}
    - Missing required field returns None (triggers retry)
    - Invalid JSON returns None (triggers retry)

    decide_stage:
    - No signals for asset logs warning and returns without storing
    - LLM returns valid JSON: stores parsed decision via decision_repo
    - LLM returns model_used="none": uses deterministic fallback, stores with model_used="none"
    - LLM returns malformed JSON: retries once with stricter prompt, then fallback with reason="LLM_PARSE_ERROR"
    - Uses timeout_decide_per_call (12s) for each LLM call
  </behavior>
