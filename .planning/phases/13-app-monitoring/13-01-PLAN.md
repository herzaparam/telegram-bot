   - Uses httpx to send to Telegram, same pattern as send_telegram_message in src/data/report.py
   - `TELEGRAM_API = "https://api.telegram.org/bot{token}/sendMessage"`
   - `async def send_alert_summary(alerts_summary: dict[str, list[str]], run_date: date) -> None`:
     - Gets token from settings.telegram_bot_token.get_secret_value(), returns if empty

     - Formats HTML message with header "Pipeline Alert - {run_date}" and sections per alert_type listing affected assets
     - Sends via httpx.AsyncClient POST to TELEGRAM_API, one message per chat_id
   - `async def send_run_completion(run_date: date, status: str, duration: float, assets: int, failed: int) -> None`:
     - Sends brief completion/failure summary message per D-05

   - `async def send_error_alert(process_name: str, error_type: str, error_message: str) -> None`:
     - Sends critical error alert for unhandled exceptions (per D-11)
     - Truncates error_message to 500 chars
     - Format: red circle header, process name, error type, truncated message

       2. Logs via structlog critical("asyncio_unhandled_exception", ...)
       3. Best-effort Telegram alert
   - NOTE: Log the original error to structlog FIRST, then attempt Telegram. Never let alert failure mask original error.
